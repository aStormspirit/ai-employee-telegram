# Нейросотрудник в Telegram

Шаблон ИИ-сотрудника на базе **Claude Code**: участники рабочего чата пишут ему задачу, он присылает план, по кнопке «Делать» правит код ваших репозиториев на GitHub, проверяет, публикует и отвечает коротким отчётом.

- **Работает круглосуточно** — без вашего компьютера.
- **Не нагружает сервер** — на сервере только лёгкий бот (~30 МБ памяти, без зависимостей). Код, сборка и публикация выполняются в облаке Anthropic.
- **На подписке Claude** (Pro / Max / Team / Enterprise) — без отдельного API-ключа.
- **Подходит под любые задачи и проекты**: сайты, приложения, боты, документация — всё, что лежит в GitHub. Проекты и правила описываются текстом в одном файле.

## Как это устроено

```
 участник чата                бот (Docker, ваш сервер)          облако Claude Code (ваша подписка)
 «@бот сделай …»  ─────────▶  проверяет чат, ─── API ───────▶  новая сессия: клон репозиториев,
                              «Принял!»          триггер        план → Telegram (кнопки)
 «✅ Делать»      ─────────▶  запускает работу ─────────────▶  правки → проверки → push → публикация
                                                                 → отчёт в Telegram
```

1. Участник отмечает бота: `@имя_бота поменяй цвет кнопки на сайте`.
2. Облачная сессия изучает код и присылает план из 1–3 пунктов с кнопками **✅ Делать** / **❌ Отмена**. Ответ на план — правки, план пересоберётся.
3. После «Делать» новая сессия вносит изменения в ветку `bot/<номер>`, запускает проверки, переносит в `main` (без force-push), ждёт публикации и при сбое откатывает изменения.
4. В чат приходит короткий отчёт: «✅ Готово! …» или «😕 Не получилось: …».

`#не_публиковать` в задаче — изменения готовятся в ветке, но не публикуются.

## Что в репозитории

| Файл | Зачем |
|---|---|
| `src/` | бот: приём сообщений и кнопок (`index.mjs`), запуск облачной сессии (`routine.mjs`), Telegram API (`telegram.mjs`), настройки (`config.mjs`) |
| `ROUTINE_PROMPT.md` | «должностная инструкция» сотрудника — промпт облачной задачи. Раздел **Проекты** заполняется под себя |
| `Dockerfile`, `docker-compose.yml` | образ и запуск на сервере |
| `.github/workflows/deploy.yml` | автодеплой бота на сервер при push в `main` |
| `.env.example` | все настройки |

## Установка

### 1. Telegram-бот
1. @BotFather → `/newbot` → получите токен.
2. `/setprivacy` → ваш бот → **Disable**, иначе бот не увидит упоминаний в группе. Если бот уже в группе — удалите и добавьте заново.
3. Добавьте бота в рабочий чат.

### 2. Облачное окружение Claude Code
[claude.ai/code](https://claude.ai/code) → меню окружения → создайте личное окружение (например, «AI employee»):
- **Environment variables**: `TELEGRAM_BOT_TOKEN=<токен бота>` — чтобы сессия могла писать в чат;
- **Network access**: Full, либо Limited с `api.telegram.org` в Allowed domains (и доменами, нужными вашим проектам).

GitHub должен быть подключён к claude.ai (Claude GitHub App с доступом к вашим репозиториям) — через это подключение сессия и пушит.

### 3. Облачная задача (routine)
[claude.ai/code/routines](https://claude.ai/code/routines) → **New**:
- **Repositories** — все репозитории, с которыми будет работать сотрудник;
- **Environment** — из шага 2;
- **Prompt** — содержимое `ROUTINE_PROMPT.md`, где в разделе **Проекты** перечислены ваши репозитории: как проверять и как публикуется каждый;
- расписание не нужно; **Triggers → API → Generate token**. Сохраните **Fire URL** и **токен** (показывается один раз).

### 4. Запуск бота на сервере

**Вариант А — вручную** (нужен Docker):
```bash
git clone https://github.com/aStormspirit/ai-employee-telegram.git ai-employee && cd ai-employee
cp .env.example .env   # заполните TELEGRAM_BOT_TOKEN, ROUTINE_FIRE_URL, ROUTINE_TOKEN
docker compose up -d --build
docker compose logs -f   # «Бот @… запущен»
```

**Вариант Б — автодеплой из GitHub Actions** (сделайте форк или «Use this template»). Settings → Secrets and variables → Actions:

| Тип | Имя | Значение |
|---|---|---|
| Secret | `TELEGRAM_BOT_TOKEN` | токен бота |
| Secret | `ROUTINE_FIRE_URL`, `ROUTINE_TOKEN` | из шага 3 |
| Secret | `BOT_ALLOWED_CHAT_IDS` | номера рабочих чатов через запятую |
| Secret | `BOT_ALLOWED_USER_IDS` | необязательно: кому можно писать боту в личку |
| Secret | `SERVER_HOST`, `SERVER_USER`, `SERVER_SSH_KEY` | SSH-доступ к серверу с Docker |
| Secret | `SERVER_SSH_PORT`, `SERVER_DEPLOY_PATH` | необязательно (22 и `~/<имя репозитория>`) |
| Secret | `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN` | куда класть образ |
| Variable | `BOT_ABOUT` | необязательно: фраза для приветствия |

Push в `main` или Actions → **Deploy bot** → Run workflow. Пока чего-то не хватает, workflow не падает, а пишет, каких секретов нет.

### 5. Подключить чат
Напишите в чате `/id@имя_бота` — бот пришлёт номер чата (вида `-100…`). Впишите его в `BOT_ALLOWED_CHAT_IDS` и перезапустите бота. Проверка: `@имя_бота` без текста — бот поздоровается.

## Настройка под свои задачи

Всё поведение сотрудника — в `ROUTINE_PROMPT.md`:
- **Проекты** — какие репозитории, как их проверять и публиковать;
- **Как писать в чат** — тон, длина, запрещённые слова;
- **MODE: plan / work** — порядок работы (ветка, проверки, публикация, откат).

После изменения промпта вставьте его заново в облачную задачу — сама она не обновляется. Правила конкретного проекта удобно держать в его `AGENTS.md` / `CLAUDE.md`: сессия читает их перед работой.

Публикация проектов — их собственные GitHub Actions (Cloudflare Pages, Vercel, Docker на сервере и т. п.): сотрудник пушит в `main` и ждёт workflow.

## Несколько сотрудников

Каждый сотрудник — отдельный Telegram-бот со своей облачной задачей, проектами и чатом. Чтобы завести ещё одного, создайте из шаблона новый репозиторий (например, `shop-employee`) и пройдите установку заново с новым ботом и новой облачной задачей. Боты работают на одном сервере независимо: папка, образ и контейнер называются по имени репозитория. Задачи одного проекта из чужого чата выполнить нельзя — у каждого бота свои `BOT_ALLOWED_CHAT_IDS` и своя облачная задача.

## Безопасность

- Задачи принимаются только в чатах из `BOT_ALLOWED_CHAT_IDS` — от **любого** участника. Добавляйте в чат только тех, кому доверяете публикацию изменений.
- На сервере нет доступа ни к GitHub, ни к аккаунту Claude — только токен бота и токен запуска одной облачной задачи.
- `TELEGRAM_BOT_TOKEN` в облачном окружении виден всем сессиям этого окружения — используйте отдельное личное окружение.
- Force-push и решение конфликтов «наугад» запрещены промптом; при сбое публикации — откат.

## Ограничения

- Лимиты облачных задач: до 30 запусков в час на одну задачу, расход — из лимитов подписки. API-триггер Anthropic помечает как экспериментальный.
- План и работа — разные сессии: контекст передаётся текстом плана из Telegram.
- Если облачная сессия не смогла написать в чат (например, нет токена), бот об этом не узнает — смотрите сессию на claude.ai/code.
- Очередь задач не хранится на сервере: каждая задача — отдельная облачная сессия.
