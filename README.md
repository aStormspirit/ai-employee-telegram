# Нейросотрудники в Telegram

Шаблон ИИ-сотрудников на базе **Claude Code**. Участники рабочего чата задают сотруднику вопросы или ставят задачи. На задачу он присылает план с кнопкой «Делать», затем правит код ваших репозиториев на GitHub, проверяет и публикует изменения и отвечает коротким отчётом.

- **Работает круглосуточно**, без вашего компьютера.
- **Не нагружает сервер**: на сервере работает только лёгкий бот (~30 МБ памяти, без зависимостей), а код, сборка и публикация выполняются в облаке Anthropic.
- **Работает на подписке Claude** (Pro / Max / Team / Enterprise), отдельный API-ключ не нужен.
- **Сотрудников может быть сколько угодно** на одном сервере: у каждого свой бот, свои чаты, свои проекты и роль, и друг с другом они не пересекаются.
- **Понимает картинки и голосовые**: фото, файлы-изображения, альбомы, ответы с картинкой; голосовые расшифровывает.
- **Помнит контекст чата** и откликается на своё имя без @.

## Как это устроено

```
 участник чата                бот (Docker, ваш сервер)          облако Claude Code (ваша подписка)
 «@бот как работает …?» ───▶  «Сейчас посмотрю…» ── API ─────▶  ответ одним сообщением
 «/task сделай …»       ───▶  «Принял!»   ─────── триггер ───▶  план → Telegram (кнопки)
 «✅ Делать»            ───▶  запускает работу ─────────────▶  правки → проверки → публикация → отчёт
```

- **Вопрос** (`@бот …`) — сотрудник разбирается и отвечает, ничего не меняя.
- **Задача** (`/task …`, «выполни задачу», «сделай задачу», «поставь задачу»):
  1. сотрудник присылает план из 1–3 пунктов с кнопками **✅ Делать** / **❌ Отмена**; если ответить на план, он пересоберёт его с учётом правок;
  2. после «Делать» вносит изменения в ветку, проверяет, переносит в `main` (без force-push), ждёт публикации и при сбое откатывает;
  3. присылает отчёт: «✅ Готово! …» или «😕 Не получилось: …».
- Картинки, приложенные к сообщению или к цитате, сотрудник скачивает и смотрит. Если картинка нужна в проекте (логотип, фон), он кладёт её в проект.
- Тег `#не_публиковать` — изменения готовятся в ветке, но не публикуются.

## Что в репозитории

| Файл | Зачем |
|---|---|
| `src/` | бот: запуск сотрудников (`index.mjs`), настройки и изоляция (`config.mjs`), сообщения, картинки и кнопки (`employee.mjs`), запуск облачной сессии (`routine.mjs`), Telegram API (`telegram.mjs`) |
| `employees.yml` | список сотрудников: роль, чаты, облачная задача |
| `scripts/employees.py` | при деплое собирает сотрудников из `employees.yml` и секретов |
| `ROUTINE_PROMPT.md` | промпт облачной задачи: стиль общения, режимы, **проекты** (заполнить), Telegram, картинки |
| `.claude/skills/task` | универсальный цикл задачи: план → правки → проверки → ревью → публикация → отчёт |
| `.claude/skills/concise-responses` | короткие ответы |
| `Dockerfile`, `docker-compose.yml`, `.github/workflows/deploy.yml` | образ, запуск и автодеплой на сервер |

## Установка

### 1. Telegram-бот (для каждого сотрудника)
1. В @BotFather выполните `/newbot` и получите токен.
2. `/setprivacy` → ваш бот → **Disable**, иначе бот не увидит упоминаний в группе. Если бот уже в группе, удалите его и добавьте заново.
3. Добавьте бота в рабочий чат.

### 2. Облачная среда Claude Code (своя у каждого сотрудника)
[claude.ai/code](https://claude.ai/code) → меню среды → создайте личную среду:
- **Environment variables**: `TELEGRAM_BOT_TOKEN=<токен бота этого сотрудника>`;
- **Network access**: Full, либо Limited с `api.telegram.org` и доменами ваших проектов в Allowed domains.

GitHub должен быть подключён к claude.ai через Claude GitHub App с доступом к вашим репозиториям.

### 3. Облачная задача (routine)
[claude.ai/code/routines](https://claude.ai/code/routines) → **New**:
- **Repositories**: репозитории проектов сотрудника **и этот репозиторий** (из него сессия берёт скиллы `task` и `concise-responses`). Скиллы можно держать и в отдельном репозитории `skills`;
- **Environment**: среда из шага 2;
- **Prompt**: содержимое `ROUTINE_PROMPT.md` с заполненным разделом **Проекты** (как проверять и публиковать каждый репозиторий). Здесь же можно задать роль, тон и формат отчёта;
- расписание не нужно; **Triggers → API → Generate token**. Сохраните **Fire URL** и **токен**: токен показывается один раз, а при перевыпуске старый перестаёт работать.

### 4. Сотрудники и секреты
Опишите сотрудника в `employees.yml`:
```yaml
shop:
  about: Я помогаю команде с интернет-магазином.   # фраза после «Привет!» в справке
  chats: [-1001234567890]                          # чаты, где любой участник даёт задачи
  routine_url_secret: SHOP_ROUTINE_URL             # Fire URL — из секрета (или routine: <URL>)
```
Секреты (Settings → Secrets and variables → Actions) удобнее всего хранить одним секретом **`ENV_FILE`**, по строке `ИМЯ=значение`:
```
SHOP_TELEGRAM_TOKEN=<токен бота>
SHOP_ROUTINE_URL=<Fire URL>
SHOP_ROUTINE_TOKEN=<токен API-триггера>
```
Имена строятся по имени сотрудника: `<ИМЯ>_TELEGRAM_TOKEN`, `<ИМЯ>_ROUTINE_TOKEN`, дефис превращается в `_`. При обновлении `ENV_FILE` вставляйте **все строки**: GitHub перезаписывает секрет целиком. Значение из `ENV_FILE` главнее отдельного секрета с тем же именем, а пустые строки ничего не затирают.

Ещё нужны секреты сервера: `SERVER_HOST`, `SERVER_USER`, `SERVER_SSH_KEY`, `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`; по желанию `SERVER_SSH_PORT` (по умолчанию 22) и `SERVER_DEPLOY_PATH` (по умолчанию `~/<имя репозитория>`).

### 5. Запуск
Push в `main` или Actions → **Deploy bot** → Run workflow. Секреты попадают на сервер **только при деплое**, поэтому после их изменения деплой нужно перезапустить.

В логе деплоя видно:
- `ENV_FILE: …` — какие строки найдены (только имена);
- предупреждение, если сотруднику не хватает секретов (его пропустят, остальные будут работать);
- `Сотрудников: N (…)` и `[имя] бот @… запущен` — кто запущен;
- `--- ошибки до перезапуска ---` — сбои предыдущей версии, например отозванный токен (`HTTP 401`).

Токены в логе маскируются.

**Без GitHub Actions:** `cp .env.example .env`, заполните, затем `docker compose up -d --build`.

### 6. Подключить чат
Напишите в чате `/id@имя_бота`: бот пришлёт номер чата. Впишите его в `chats` в `employees.yml` и запустите деплой. Проверка: `@имя_бота` без текста — бот поздоровается. В неподключённом чате бот отвечает «Я пока не работаю в этом чате» и показывает номер чата.

## Контекст, имя, голосовые
- **Контекст чата**: бот держит в памяти последние 50 сообщений каждого своего чата (до 12 часов) и передаёт 20 последних вместе с задачей (поле HISTORY). Только в оперативной памяти, после перезапуска — пусто.
- **Обращение по имени**: `names: [Макс]` в `employees.yml` — бот откликается на «Макс, …», «Макс …» в начале или «…, Макс?» в конце сообщения, без @.
- **Голосовые**: расшифровываются через OpenAI-совместимый сервис (OpenAI, Groq и др.); бот реагирует, если в голосовом его позвали по имени или это ответ ему, расшифровки попадают и в контекст. Включается строками в `ENV_FILE`:
  ```
  STT_API_URL=https://api.groq.com/openai/v1/audio/transcriptions
  STT_API_KEY=<ключ>
  STT_MODEL=whisper-large-v3-turbo
  ```
  Для OpenAI: `https://api.openai.com/v1/audio/transcriptions`, модель `whisper-1`. Без них голосовые игнорируются. Расшифровываются все голосовые в подключённых чатах (до 5 минут) — иначе бот не услышит своё имя.

## Несколько сотрудников
Каждый сотрудник — отдельная запись в `employees.yml`, свой бот, своя облачная среда и своя облачная задача. Сотрудник принимает сообщения только из своих чатов и запускает только свою облачную задачу, поэтому из чата одного проекта нельзя запустить работу над другим. Если один чат или токен указан у двух сотрудников, второй не запустится, причина будет в логе. Сбой одного бота не останавливает остальных.

## Настройка поведения
- **Промпт** (`ROUTINE_PROMPT.md`): роль, тон, проекты, проверки, публикация. После правки вставьте его в облачную задачу заново, сама она его не подтянет.
- **Скилл `task`**: общий порядок работы над задачей, один для всех сотрудников. Особенности проекта задаются в промпте и `AGENTS.md` репозитория, а не в скилле.
- **Отчёт по расписанию**: создайте ещё одну облачную задачу с расписанием (cron) в той же среде, промпт должен отправить отчёт в `CHAT_ID` командой из раздела «Как писать в Telegram».

## Безопасность
- В подключённых чатах задачи принимаются от **любого** участника. Добавляйте в чат только тех, кому доверяете публикацию изменений.
- На сервере нет доступа ни к GitHub, ни к аккаунту Claude: там только токены ботов и токены запуска облачных задач.
- `TELEGRAM_BOT_TOKEN` в облачной среде виден всем сессиям этой среды, поэтому у каждого сотрудника должна быть своя личная среда.
- Force-push и решение конфликтов «наугад» запрещены, при сбое публикации изменения откатываются.

## Ограничения
- Лимиты облачных задач: до 30 запусков в час на одну задачу, расход идёт из лимитов подписки. API-триггер Anthropic помечает как экспериментальный.
- План и работа — разные сессии: контекст передаётся текстом плана и картинками.
- Если облачная сессия не смогла написать в чат (нет токена, закрыт `api.telegram.org`), бот об этом не узнает. Смотрите сессию на claude.ai/code.
- Очередь не хранится на сервере, картинки задач хранятся в памяти бота до перезапуска.
