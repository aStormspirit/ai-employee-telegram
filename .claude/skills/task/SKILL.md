# Цикл задачи

Всё, что зависит от проекта и сотрудника, задаёт промпт облачной задачи, а не этот скилл:
- поля запуска и отправка в Telegram — раздел «Связь с Telegram» / «Как писать в Telegram»;
- проекты, их проверки и публикация — раздел «Проекты» и AGENTS.md репозитория;
- тон, длина и формат сообщений в чат — раздел «Как писать в чат» (если его нет — коротко, простым текстом);
- выбор моделей и подагентов — раздел «Экономия», если он есть.

## Подготовка (plan и work)
1. Картинки (IMAGES) скачай и посмотри по промпту. Роль картинки:
   - образец (макет, скриншот ошибки, пример стиля) — только для понимания, не коммить;
   - материал (логотип, фон, иконка, картинка для бота) — положи в папку ассетов проекта
     (как принято в AGENTS.md), уменьши и сожми (webp, если формат поддерживается), упомяни в плане.
     Новая картинка, видимая пользователю, — изменение дизайна: только после «Делать».
   - непонятно — спроси в плане одной строкой.
2. Определи затронутые проекты (если неясно — спроси в плане). В каждом прочитай AGENTS.md / CLAUDE.md
   и, если есть, .ai/CURRENT_TASK.md и .ai/STATE.md — только выжимку.
3. TASK «принять» / «откатить» / «доработать» — примени к последней задаче из .ai/tasks/ (если папки нет — спроси).

## MODE: plan — план (код не меняй)
1. Разведка: нужные файлы и потребители контрактов, точечно (grep по месту). Данные задачи — TASK (полный текст), CONTEXT, HISTORY, картинки.
2. План: шаги, риски, критерии приёмки. Если в проекте есть .ai/ — запиши в .ai/tasks/<TASK_ID>.md
   в ветке task/<TASK_ID> и запушь (не в основную ветку).
3. Отправь в Telegram ОДНО сообщение. Первая строка и пустая строка после неё — строго так
   (бот разбирает сообщение по ним):

   📋 Задача №<TASK_ID>[ · без публикации]: <TASK одной строкой>

   <план в стиле промпта: что изменится и как будет работать для пользователя; для дизайна — макет или где его взять;
   риски — потеря прод-данных, реальные деньги, нет нужного секрета, массовые рассылки; вопросы — в конце>

   Если всё верно — нажмите «Делать». Если нужно что-то изменить — ответьте на это сообщение.

   « · без публикации» — только если NO_DEPLOY = yes.
   BUTTONS='[{"text":"✅ Делать","callback_data":"ok:<TASK_ID>"},{"text":"❌ Отмена","callback_data":"no:<TASK_ID>"}]'.
   Есть FEEDBACK — переделай PREVIOUS_PLAN и отправь заново в том же формате.
4. Стоп. «Делать» придёт новым запуском MODE: work с APPROVED_PLAN.

## MODE: work — реализация (после «Делать»)
1. Что делать — APPROVED_PLAN (и .ai/tasks/<TASK_ID>.md, если есть). Данные — ORIGINAL_TASK (полный исходный текст: таблицы, цифры, ссылки), FEEDBACK, CONTEXT, HISTORY и картинки. Не проси прислать данные заново, если они есть там; спрашивай, только если их действительно нет.
2. Правки в ветке task/<TASK_ID> от свежей основной ветки.
3. Проверки проекта (из промпта / AGENTS.md); фиксируй реальный результат, ошибки исправь.
4. Ревью: diff против плана и критериев → PASS или FAIL. FAIL — исправь и проверь снова
   (не больше 3 кругов, потом стоп и отчёт).
5. Коммит с понятным сообщением, push ветки. NO_DEPLOY = yes — на этом всё, переходи к отчёту.
6. Перенеси в основную ветку: подтяни свежую, rebase или merge, обычный push — никогда не force-push.
   Конфликт — не решай наугад: стоп, изменения остаются в ветке, сообщи.
   Меняется контракт между сервисами — правь всех потребителей; порядок: API → клиенты.
7. Дождись публикации (workflow деплоя этого репозитория для своего коммита; gh run watch <id> --exit-status | tail -n 5
   или инструменты GitHub actions_list / actions_get). Упала — git revert своих коммитов в основной ветке, push,
   сообщи об откате. Пропущена из-за ненастроенных секретов — скажи, что изменения сохранены, но появятся после
   настройки публикации.
8. Если в проекте есть .ai/ — кратко обнови .ai/CURRENT_TASK.md, .ai/STATE.md, строку в .ai/CHANGELOG.md.

## Отчёт в Telegram (без кнопок, в стиле промпта)
- получилось: «✅ Готово! <задача>» — что изменилось и где увидеть; при NO_DEPLOY — что готово, но не опубликовано;
- не получилось: «😕 Не получилось: <задача>» — что помешало и что всё осталось как было;
- нужно решение: «❓ <вопрос>».
Если промпт разрешает технические подробности — добавь проверки и <repo>@<sha>; иначе оставь их в итоговом ответе сессии.
